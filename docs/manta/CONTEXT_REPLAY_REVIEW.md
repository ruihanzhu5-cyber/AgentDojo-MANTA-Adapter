# Context 重放实现与自查记录

日期：2026-10-19。范围：第一阶段的 24 次局部 worker 重放；未启动真实模型请求。

## 结论

第一阶段通过代码自查、9 项新增无网络测试、3 项原预算测试和 12 项原指标测试。
命令行预检通过，输入、只读工具前缀、原生工具 schema 与冻结任务清单均可生成。
此结论是工程验收，不保证远程服务在之后运行时不会超时或报错。
没有进行跨模型独立审计，也没有将脚本化模型行为作为研究结果。

## 自查发现和修正

| 问题 | 修正与证据 |
|---|---|
| 原生阶段工具日志没有完整 output，不能用来重建环境 | 按阶段归属与官方 FunctionsRuntime 台账逐项对齐，使用真实 output，并验证全序列覆盖 |
| 原前缀中攻击已经成功，整轮分数无法衡量下游 | 按续跑前后的 web_requests 边界计算新增调用；保留 baseline/full-prefix 分数用于展示饱和 |
| MANTA 导入会自动加载 .env，可能重新引入参数覆盖 | 在导入后再次清理 MAS_/MANTA_/OPENROUTER_；固定本轮原生默认参数，保留已有 API 凭据 |
| 只删除明显 payload 可能遗漏目标 URL 和衍生叙述 | 显式处理四类字段、保存 diff，发现其他字段残留则拒绝运行 |
| 重新渲染 M0 context 可能额外改变格式 | 使用原生 indent=2 JSON 格式，并检查 packet 以外的 context 字段相同 |
| 不完整执行可能被误计为安全 | 错误、截断、提前停止、恢复性超时均排除有效分母；保留已观察到的目标动作 |
| 重启可能重复收费或混入旧数据 | 同目录文件锁、存活子进程检查、冻结配置/fixture 校验；跳过有效结果，不完整项显式重试，最多三次尝试 |
| 首轮异常后仍继续扩量 | 先运行 8 组；只有工程完整才继续剩余 16 次，与攻击结果无关 |
